## 1. 项目是什么

在 **GNSS 被拒止 / 不可用** 的场景下，用手机相机 + 星图 + IMU 做天文定位的现场工具：

- **星光定位**：拍星空，识别星图，结合重力方向解算天顶 → 位置（单历元）；
- **太阳/月亮定位**：拍太阳/月亮圆面，结合星历、重力与时间解算位置（多历元可联合）；
- **两体 / 水镜**：同框天体、水面镜像等辅助约束（当前作为候选与诊断，未全部进入正式解）；
- **现场采集**：把定位所需的全套数据（RAW/YUV 帧、IMU、GNSS 真值、相机参数、日志）打成 ZIP，
  带回后离线分析；App 内也可对已采集包做太阳/月亮高度 + 星光 FixObs 的**联合解算与结果展示**；
- **标定**：IMU 六位置零偏、点阵内参、星空手眼外参（离线自动估计 + 安全闸）；
- **无地图结果页**：WGS84 经纬度、UTM、局部 ENU、1σ/95% 概率椭圆、逐包贡献、误差图。

本项目是**实验/测量工具**，不是消费级导航；精度受几何、标定、系统误差限制，结果页会显式标注是否可信。

## 2. 主要功能

### 2.1 首页

- 自设计 Logo、名称、版本号、`powered by DSH` 徽章；
- 4 个上滑展开/下滑收起的面板：
  - **原理说明**：核心公式、各定位分支、术语表（正式定义 + 大白话）、联合解算/结果怎么读、高级设置影响；
  - **使用说明**：现场流程、镜头选择、水镜操作、内参适用场景、场景处理路径、重标定条件；
  - **状态聚合**：相机/内参/外参/IMU 实时采样/GNSS/时钟（可自动 NTP 对时）/电量/存储/版本；
  - **关于**：技术栈、隐私边界、DSH 说明。

### 2.2 现场采集

- **预检**（底部弹出标签）：相机 id/朝向/硬件级别/分辨率/焦距/RAW、曝光/ISO 范围、内参来源、外参、IMU 零偏、时钟；
- **相机与预览**：主摄 0 / 超广角 3 / 长焦 4；默认相机与预设可自动切镜头；
- **参数**：帧数、曝光（100 µs–8 s）、ISO、预览模式（自动/找星/跟随/月亮/太阳/白天月亮）、放大、HDR、预览调参；
- **预设**：夜景星空、月亮、太阳、白天月亮、水镜等；可新增/编辑/删除、**导入/导出 JSON**、指定镜头；
- **对准辅助**：磁罗盘方位/俯仰、候选天体、可见星数估计（按 FOV + Bortle 光污染）、水镜托盘距离；
- **采集**：手动/自动曝光，RAW 优先、YUV 兜底；太阳模式安全确认与曝光上限；
- **现场质量反馈**：检测星数、匹配数、云量、PSF、稳定度、可解算提示；
- **安全确认**：太阳滤镜、长曝光稳定、低存储提醒（<1 GB 弹窗）；
- **合成样例**：不拍照，生成带合成星点/IMU/GNSS 的完整采集包，用于验证打包/离线链路。

### 2.3 标定

- **IMU 零偏**（六位置法，室内）；
- **内参**（点阵，手动 12 帧；内置 A4 点阵 PDF/PNG，可一键导出到 `下载/StarPosition`）；
- **外参**（三脚架星空手眼，手动 8 帧；采集结束后**离线自动估计并安全写入**，与现外参差 >3° 不写）；
- 标定结果/失败都会给原因与下一步；标定包与定位包按类型前缀区分。

### 2.4 会话（采集包）

- 列表、详情（真值/相机/内参/外参/备注）、重命名、分享 ZIP、**导出到下载**；
- 存储统计（包数、ZIP 大小、原始目录、可用空间）；
- **清理**：原始目录（仅删有 ZIP 的，保留 ZIP）、ZIP 多选/旧于 7/30/90/180 天、7 天回收站；
- 包名类型前缀：`sun-/moon-/star-/ext-/cal-` + 相机标签 `camX` + 时间，例如 `sun-cam0-session-20261125-...`。

### 2.5 结果页（无地图）

- **设备内解算**：太阳/月亮视高度 + 星光 FixObs 联合（两体 FixObs 接口已支持，自动提取尚未接入；同地点/同镜头/同设备为前提）；
- 坐标：**WGS84 经纬度为主**，UTM/高斯投影，局部 ENU（参考原点可选解算点/GNSS 真值）；
- **1σ 与 95% 概率椭圆**（半轴/方位/面积）；
- 有 GNSS 真值才显示误差与 T 级；无真值只显示内部椭圆并明确"未验证"；
- 逐包贡献（观测数/残差）、留包复核点误差图、自适应比例尺、N-S 方向；
- **系统偏差迁移**：用有真值的参考包估计垂直偏差 δv，手动确认后迁移到无真值包；
- 水镜包：反射像检测 → 镜像天顶 vs IMU 天顶对照（诊断，未进入位置解）；
- **镜头一致性**：所选包镜头不一致默认拒绝解算，需确认各自已标定；
- 当前参数提示（坐标格式/星垂修正/误差底噪/剔除复核点/星表）；
- **复制结果 / 导出结果 JSON**。

### 2.6 设置

- **外观**：夜视（琥珀）全 App 统一、**色觉辅助（蓝/橙）**；
- **高级**：
  - 自动 NTP 对时、NTP 服务器选择（阿里云/中国池/亚洲池/全球池/Cloudflare/Google + 自定义，支持测试连接）；
  - 星光垂直修正开关（StarVertical，来自星光+GNSS 真值标定拟合）；
  - 默认相机、坐标格式（十进制度/DMS）；
  - 联解系统误差底噪、结果页剔除复核点数量；
  - 光污染等级（Bortle 1/3/5/7/9）；
  - 星表版本：J2000 / J2016.0；
  - 曝光/ISO 预设管理（导入/导出 JSON）；
- **诊断**：自检、浏览诊断日志（文件最近 2000 行，级别着色，过滤）、分享日志；
- **数据与隐私**：存储位置/用途、清理入口、版本/仓库说明。

### 2.7 分析与算法

- 星表：HYG v41（mag ≤ 7，15,599 颗，含自行；J2000）与 J2016.0 传播版；
- 星图识别：三角形哈希 + RANSAC/假设检验；姿态：Wahba/SVD；
- 天体：太阳视位置（TT/ΔT、章动、光行差、Meeus 25.10）、月亮（含视差/折射）、行星；
- 时间/坐标：IAU2006 岁差、IAU2000A 章动（截断）、GAST、Bennett 折射、WGS84；
- 定位：星光单历元 T1；日月高度与联合解算（可估钟差 δt / 垂直偏差 δv）；
- 结果：1σ/95% 椭圆、DOP/残差、逐包贡献、留包复核、系统偏差迁移。

## 3. 现场工作流（推荐）

1. **设备准备**：标定（零偏 → 内参 → 外参），设置默认相机/NTP/星表；
2. **到达现场**：状态聚合确认时钟/存储/权限；
3. **采集**：选预设 → 确认镜头 → 对准辅助找星/找日月 → 开始采集（同一地点至少上午+下午，方位覆盖 ≥60°）；
4. **命名**：包名自动带类型+镜头+时间；必要时改名；
5. **导出**：分享/导出 ZIP（自动标记"已导出"）；
6. **离线分析**：把 ZIP 放到 `field-inbox/`，用 JVM 分析/联合解算；
7. **App 内结果**：结果页勾选同地点/同镜头包 → 联合解算/单包解算 → 有真值校验，无真值只给椭圆；
8. **清理**：会话页/清理页删除原始目录（保留 ZIP）、旧包进回收站。

## 4. 构建与测试

```powershell
. E:\dsh-toolchain\env.ps1
cd D:\Documents\deepseek-harness\default-workspace\star-positioning

.\gradlew.bat :app:testDebugUnitTest    # 快测试（重型实验默认排除）
.\gradlew.bat :app:assembleDebug        # 产出 app/build/outputs/apk/debug/starpos-<版本>-debug.apk
```

- 版本号只在 `app/build.gradle.kts` 的 `appVersionCode` / `appVersionName` 修改；
- 星表资产：
  - `app/src/main/assets/stars.bin`（HYG J2000，由 `catalog/build_catalog.py` 生成）；
  - `app/src/main/assets/stars-j2016.bin`（同表按自行传播到 J2016.0）；
- 重型实验（含真实采集包/长时分析）需要 `-PfullAnalysis=true --tests "*Xxx*"`；
- 设备安装：`adb install -r app/build/outputs/apk/debug/starpos-<版本>-debug.apk`。

## 6. 数据与隐私

- 帧、IMU、GNSS 全部在**本机**处理；除用户主动点"网络对时/分享/导出"外不联网；
- 采集包含位置信息，属于敏感数据：**不公开上传**、不用于跟踪他人；仓库与分支当前均为私有；
- 分享/导出由用户显式操作；ZIP 在 `Android/data/com.dsh.starpos/files/sessions`，可删除/回收站；
- 未来若开源：需要先清理历史中的现场数据/私有路径/设备信息，并补齐 LICENSE/构建说明。

## 7. 已知限制（诚实边界）

1. **联合解算精度仍依赖几何与系统项**：太阳/月亮单历元几何弱；实测同一批数据有 200 km 级误差，
   加入星光 FixObs 的样本曾到 17.7 km（T1），不能保证普遍达到 T1；
2. 星光分支的垂直修正（StarVertical）来自**特定设备+标定的拟合**（dt≈(2.97,−0.03,−4.84)°），换机/重标定需重拟；
3. 结果页内部椭圆只反映随机误差，**系统误差可能使其偏乐观**；无 GNSS 真值时不给 T 级；
4. 内参自标定只拟合 fx/fy/cx/cy；强畸变镜头/广角边缘精度有限；
5. 两体/水镜/月亮轨道等分支在 App 内结果页仅部分接入（FixObs/高度联合为主）；
6. 星表为 HYG（Hipparcos 系亮星），未内置 Gaia 暗星；J2016 与 J2000+自行等价；
7. 旧包若没有类型前缀/备注，结果页不自动识别；可用重命名补类型；
8. 发射/推广前仍需多设备、多地点、多天气的外场验证。

## 9. 本地备份建议

- **需要单独备份**：GitHub 当前推送受阻，且仓库为私有；本机磁盘损坏会同时丢失代码、未推送提交与现场数据。
- 建议至少两份、离线/异地：
  1. **源码**：`git bundle create starpos-backup.bundle --all`（可离线恢复全部历史），
     外加一份去掉 `build/`、`.gradle/`、`app/build/`、`*.apk` 的工作区副本；
  2. **现场数据**：`field-inbox/` 与设备 `sessions/` 单独加密归档（含个人位置信息），
     按"原始 ZIP 必留、原始目录可弃（可重打包）"控制体积；
  3. **关键资产**：星表、点阵、`config/`、签名/发布说明单独保存。
- 频率：每次外场采集/版本里程碑后各一次；至少保留最近 2–3 份，且**定期做恢复演练**。
- 不要把私钥、PAT、设备备份、现场位置数据放进公开仓库；开源前先清理历史。
- 网络可用时推送 `ui-redesign` 与 `opensource-prep`，可减少对本地备份的依赖（但不替代离线备份）。
